# Reporting standard

The project is structured to support PRISMA 2020, PRISMA-S and PRISMA-LSR
reporting. It does not claim full compliance until the corresponding evidence
is complete.

| Reporting evidence | Repository source | Current state |
|---|---|---|
| Objectives, scope, eligibility | Protocol + codebook | Active |
| Information sources/platforms | Source registry + expansion strategy | Active; expand per execution |
| Exact search strategies/dates | Discovery events, execution records and cycle issue | Required for every new run |
| Deduplication and selection | Identifiers + screening decisions | Active model |
| Study-selection flow | Versioned aggregate release metrics | Pending reconciled E1–E3 data |
| Full-text exclusions/reasons | Screening decisions | Required when full text is sought |
| Data items and coding | Taxonomy + paper codes | Initial taxonomy only |
| Risk-of-bias/quality appraisal | Future appraisal registry or reason for non-use | Not yet implemented |
| Synthesis methods | Protocol amendment before synthesis | Evidence map only today |
| Living-update methods | Expansion strategy + automation runbook | Active model; first complete E1–E3 cycle pending |
| Registration/amendments | Version + changelog | Active; persistent registration pending |
| Funding/conflicts/support | Release notes | Required before 1.0 |
| Availability/citation | CFF + release manifest | Active; DOI/licence decision pending |

Every release must report the database/citation-search coverage date separately
from metadata verification, decision dates and release date. Failures must never
be counted as zero-result searches. The public site must call itself a living
archive until the flow and stop-rule evidence support a stronger claim.
